# 0.4.0：三個光源端點各寫自己的矩陣

本文件說明 0.4.0 相對 0.3.1 改了什麼、為什麼改、預期在畫面上造成什麼方向的變化，以及哪些部分仍然缺供體資料。

一句話結論：**0.3.x 把 A1 端點的六係數蓋進 B／A1／A2 三個端點；0.4.0 改成每個端點寫自己的六係數（仍各自鋪滿 16 槽）。色度、Gamma、程式補丁與四個整檔雜湊完全不變。**

## 1. 實拍回饋

2026-10-19 使用者以 0.3.1 實拍回饋：

- 原本偏掉的红、橙已經校準；
- 綠色色相偏移不夠。

紅橙正確、綠色不足，這個組合本身就是線索：三個端點對紅橙的差異很小，對綠色的差異明顯。若機身當時讀的不是 A1 端點，就會出現「紅橙對、綠色差」的結果。

## 2. 原因：A1 被寫進三個端點

576B 記錄是三個光源端點，每個端點 192B = 16 槽 × 12B 六係數。供體的實際資料裡，三個端點的六係數並不相同：

| 外觀 | 端點 | 六係數 a,b,c,d,e,f | 展開 3×3 綠列 |
|---|---|---|---|
| FL2 | B | `113,-141,-68,88,128,103` | `68, 1044, -88` |
| FL2 | A1 | `-17,-47,-46,113,406,184` | `46, 1091, -113` |
| FL2 | A2 | `225,-242,-80,77,371,-5` | `80, 1021, -77` |
| FL3 | B | `57,-231,81,-255,200,214` | `-81, 850, 255` |
| FL3 | A1 | `138,-221,-42,-128,253,-17` | `42, 854, 128` |
| FL3 | A2 | `225,-265,104,-238,366,-47` | `-104, 890, 238` |

綠色輸入主要看第三欄（R↔G、G↔B 的交叉項）。FL2 的 A1 是 `46 … -113`，B 是 `68 … -88`，A2 是 `80 … -77`；這些差異會直接改變綠色的色相角，但對紅、橙的影響小得多。

0.3.x 把 A1 那一組寫滿 48 槽，等於「不论機身讀哪個端點，都給它 A1 的判讀」。若實際讀的是 A2，綠色就少了 A2 特有的偏移。

## 3. 資料來源與交叉驗證

R5 倉庫只公布 block13 group1 slot0，也就是 A1 端點。B／A2 兩組來自同一個 FX2 1.01 供體，資料在 `sony-a7m4-custom-firmware` 的 `docs/fl23-colour-comparison-20261018/data/recipe_comparison.json`：欄位 `details[].matrix_first9_by_endpoint`，方案標記為「FX2 原厂」。

一致性檢查（`fl23_color.py verify` 會重跑）：

- 三組 3×3 逐列行和都是 1024（中性輸入不偏色，與六係數展開式吻合）；
- 每組以 `a=-M01, b=-M02, c=-M10, d=-M12, e=-M20, f=-M21` 反算後可展開回原 3×3；
- FL2／FL3 的 A1 端點與 R5 公布的 `matrix_3x3` 逐項相同——兩個獨立文件互相印證了端點順序與數值。

## 4. 這次改了哪些位元組

| 外觀 | 色度 | 矩陣 | 合計 | 矩陣記錄 SHA-256（前 16） |
|---|---:|---:|---:|---|
| FL2 | 0 | 256 | 256 | `79e9d029…` → `7a15baf6…` |
| FL3 | 0 | 272 | 272 | `f2099cd9…` → `d2783261…` |
| 合計 | 0 | 528 | **528** | |

色度 64B、六條 Gamma 記錄、AP／CP 程式補丁、四個原生模組與 `ORIGINAL`／`FINAL` 整檔雜湊都沒有變動；寫入窗口（`core.colour_write_spans()`）與回復判定也不需要改，因為矩陣記錄本來就是整段 576B 覆寫。

## 5. 預期方向（代數試算，非機內像素）

`python fl23_color.py hue` 會列出每個端點在各色相角造成的 Δh／ΔC。取 L\*=55、C\*=45 的取樣點：

| 輸入色相 | FL2 A1 | FL2 A2 | 差 | FL3 A1 | FL3 A2 | 差 |
|---|---:|---:|---:|---:|---:|---:|
| 30°（橙） | +12.1 | +12.9 | +0.8 | +11.8 | +7.2 | −4.7 |
| 45°（橙黃） | +9.8 | +10.8 | +1.0 | +8.4 | +2.2 | −6.1 |
| 120°（綠） | −0.5 | +4.6 | +5.1 | +2.0 | +3.0 | +1.0 |
| 135°（綠） | −3.8 | +2.4 | +6.2 | +2.4 | +4.0 | +1.6 |
| 150°（青綠） | −2.1 | +5.0 | +7.1 | +5.8 | +7.4 | +1.6 |

重點：

- **FL2**：A2 端點把綠往高色相角（綠→青）比 A1 多推 5–7 度，紅橙幾乎不動（30°/45° 差 1 度內）。
- **FL3**：A2 端點只多推 1–2 度；B 端點反而把綠往低色相角（綠→黃）推約 5 度。若你的機身在 FL3 上走的是 B 端點，這次的方向會與 FL2 相反，實拍時請分開判斷 FL2 與 FL3。
- 這是「矩陣作用在線性 sRGB 上」的代數近似：不含去馬賽克、白平衡、Gamma 與色度階段，數值不代表機內最終像素，只用來看方向與相對大小。
- 同一個 FX2 供體在 A7M4 上的實拍量測（`指标汇总.csv`／`逐色块数据.csv`，方案「FX2 原厂」對「当前配方」＝三端點對固定 A1）顯示：綠色塊色相差 +2.0 至 +4.5 度、黃色塊 −1 至 −4 度、紅橙 −2 度上下，方向與上表一致。那是 A7M4 的樣本，不是 A7C II 的量測。

## 6. 仍然缺的部分

1. **逐槽（色溫）矩陣。** 每個端點有 16 槽，公開資料只有槽 0；0.4.0 仍把同一組六係數鋪滿該端點的 16 槽。實機在同一光源下若選到非 0 槽，會用槽 0 的判讀。A7C II 自己的庫存外觀顯示 16 槽之間差異不小（同一組、同一端點，綠色色相在槽間可差 5–11 度），這是下一個可量化的殘差來源，但沒有 FX2 供體值就無法逐槽還原。
2. **圖片來源以外的欄位。** Gamma 六條記錄、`0x780F` 完整 276 位元組仍無公開位元組。
3. **端點順序。** B／A1／A2 的順序沿用記錄佈局與 0.1.0 的分析；A1 與 R5 公布值相同是這次最強的佐證，但未在 A7C II 上逐端點實測。

## 7. 自檢

```text
python fl23_color.py inspect      # 三端點主槽、各自 16 槽是否統一、等於參考值的槽數
python fl23_color.py verify       # 48/48 槽等於參考端點值、A1 與 R5 一致、清單雜湊自洽
python fl23_color.py hue          # 端點間色相位移對照（--json 可輸出）
python -m unittest discover -s tests     # 34 項離線測試
python app.py check-package
```

`fl23_color.py port --fill unified` 可重建 0.3.x 的「三端點同值」記錄，只用於回退比對；正式資產一律用預設的 `endpoints`。

## 8. 驗證邊界

本次仍是純離線資產變更：沒有寫相機、沒有重拍、沒有測色。改動只證明「三個端點等於供體公布值、端點內部 16 槽一致」，不證明畫面等於 FX2 或 A7R V 的 FL2／FL3。0.3.1 與更早的 ZIP 全部保留，可隨時回退。
