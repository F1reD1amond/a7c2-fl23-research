# 0.3.0：实拍反馈的排查与矩阵全槽填充

0.2.0 装到机身后，实拍反馈有两条：

1. 黑色没有很好地下沉；
2. 红、黄不够偏橙，与原厂观感有距离。

本文件记录逐项排查的结论、改了什么、以及哪些问题还没解决。

## 1. 一句话结论

**Gamma 不是主因，矩阵只覆盖了 1/16 才是。** 0.2.0 把 R5 的照片矩阵写进了每个光源端点的槽 0，但 576B 矩阵记录有 16 个温度槽，其余 45 个槽（3 端点 × 15 槽）仍是 Alpha 1 II 的矩阵。相机按色温／光源选槽，大部分拍摄条件落到旧矩阵上，所以看起来「R5 移植没生效」。

0.3.0 把同一组六系数铺满 48 个槽，共改 795 字节。

## 2. Gamma 排查

### 2.1 记录结构

A7C2 的 FL2／FL3 Gamma 是 CP 补丁块 `0x1100b80` 里的 4 条记录，每条 576 字节：

| 偏移 | 用途 | 572B 前缀 SHA-256 前 16 位 |
|---|---|---|
| `0x000` | FL2 照片槽 0–5 | `bcdee141b8835b4c` |
| `0x240` | FL2 照片槽 6 | `d87a1db7a7b6d729` |
| `0x480` | FL3 照片槽 0–5 | `ca5b168a42e100b8` |
| `0x6C0` | FL3 照片槽 6 | `0a688c6c40475e7e` |

记录之后是 14 行 × 7 个指针的 Gamma 表。FL2 行 = 6 个照片槽指向 `0xE02310`（槽 0–5 的记录），第 7 项指向 `0xE023D0`（槽 6 的记录）。**照片日常走的是槽 0–5 那一条**，不是槽 6。

### 2.2 与 FX2 的差异

M4 报告给出 FX2 原厂 FL2 三条记录的 572B 哈希与 6 个采样点：

| 曲线 | 572B SHA 前 16 位 | 采样点 0/16/32/64/96/127 |
|---|---|---|
| FX2 照片槽 0–5 | `f28fe572c6fb7356` | 0, 9259, 18537, 37052, 106350, 130944 |
| A7C2 照片槽 0–5 | `bcdee141b8835b4c` | 0, 9259, 18537, 37052, 106350, 130944 |
| FX2 照片槽 6 | `8cb914f31e435475` | 0, 18526, 37053, 68457, 118863, 130944 |
| A7C2 照片槽 6 | `d87a1db7a7b6d729` | 0, 17367, 34735, 64096, 111511, 122844 |

- 照片主曲线：六个采样点**逐点相同**，说明低中调（含黑色段）与 FX2 一致；整条哈希不同，差异在未公开的采样点之间与 128 项之后的高光段。
- 照片槽 6：A7C2 的采样等于 FX2 的**视频**槽 6，比 FX2 照片槽 6 低约 6.6%。槽 6 是非常用分支，本次没有动。

### 2.3 Knee 参数

R5 文档要求 FL2／FL3 的 Gamma knee point = 512、knee slope = 1024（RAW 标签 `0x780C`／`0x780D` 分别为其 2 倍／16 倍）。A7C2 四条记录的 `0x228..0x237` 全为 0，即空指针，固件走默认 512／1024——**与目标值恰好相同**，等效，不需要改。

### 2.4 结论

照片曲线的低中调与 FX2 逐点一致，knee 等效，所以「黑色不下沉」不能归因于 Gamma 记录。要完全替换成 FX2 曲线需要 FX2 1.01 的 CP 字节（偏移 `0xdb32bc` 等），本仓库没有这批数据。

## 3. 矩阵排查

### 3.1 记录布局

576B = 三个 192B 端点（B／A1／A2），每个端点 16 槽 × 12B 六系数，共 48 个 3×3 矩阵。

```
M = [[a+b+1024, -a,      -b     ],
     [-c,       c+d+1024, -d     ],
     [-e,      -f,        e+f+1024]]
```

### 3.2 0.1.0 与 0.2.0 的实际填充

| 版本 | 槽 0 | 槽 1–15 |
|---|---|---|
| 0.1.0 | Alpha 1 II 矩阵 | Alpha 1 II 的 15 个温度／光源矩阵 |
| 0.2.0 | **R5 矩阵** | 仍是 Alpha 1 II |
| 0.3.0 | R5 矩阵 | **R5 矩阵（同一组）** |

0.2.0 的 `fl23_color.py inspect` 会直接显示 `等於 R5 的槽：3/48`。槽间差异并不小：同端点内，槽与槽展开后的矩阵元素最大差在 263–616（满量程 1024 的 26%–60%），足以让红黄判读明显不同。

### 3.3 为什么这能解释两条症状

R5 的 FL2 矩阵是：

```
[[ 960,    17,    47],
 [  46,  1091,  -113],
 [-406,  -184,  1614]]
```

对比 Alpha 1 II 的：

```
[[ 856,  -140,   308],
 [  28,  1099,  -103],
 [-190,  -225,  1439]]
```

R5 的红行把绿分量从 −140 提到 +17、蓝分量从 308 压到 47，这正是「更偏橙」的方向；蓝行把红、绿负得更深（−406／−184），暗部蓝通道被压得更低，观感上更「沉」。当相机选到非 0 槽时，这两项都不生效，回到 Alpha 1 II 的判读——与实拍反馈的两条症状方向一致。

## 4. 改动

`fl23_color.py port` 默认改为 `--fill all`：

```text
python fl23_color.py inspect        # 先看 48 槽里有多少等于 R5
python fl23_color.py port           # 只打印将变更的字节数
python fl23_color.py port --write   # 写入并刷新清单
```

0.2.0 → 0.3.0 的实际变更：

| 外观 | 变更字节 | 矩阵 SHA-256 前 16 位 |
|---|---:|---|
| FL2（参数 55／槽 23） | 435 | `2f429124…` → `79e9d029…` |
| FL3（参数 56／槽 25） | 360 | `b5eed1a9…` → `f2099cd9…` |

色度不变，Gamma、AP／CP 程序补丁、四个原生模块、`ORIGINAL`／`FINAL` 整档哈希全部不变。

`core.colour_record()` 的写入前不变量同步收紧：48 个槽只要有任意一组与第一组不同就拒绝写入，0.2.0 那种混合记录无法再流入安装流程。

## 5. 取舍

- **得到**：任何色温／光源分支都使用同一套 R5 判读，不再出现「部分场景是 Alpha 1 II」。
- **失去**：逐槽的温度／光源微调。R5 的真实做法是整块 3072 字节（4 bank × 768B）从 FX2 复制，本仓库没有那批字节；统一填充是派生选择，不是原厂自适应矩阵。
- **风险**：极端色温（高色温阴影、低色温白炽灯）下可能出现偏色，因为不再有分槽补偿。若实拍发现某一色温明显异常，可用 0.2.0 的 ZIP 回退，或提供该场景的样片再评估。

## 6. 实拍验证建议

装好后按同一场景、同一曝光、同一白平衡分别拍 FL2／FL3 与 ST，重点看：

1. 阴影里的黑是否比 0.2.0 更实；
2. 红色（砖墙、唇色）与黄色（暖光下的白墙、木色）是否更偏橙；
3. 高色温（阴天、蓝调时刻）是否出现新的偏色；
4. FL2 与 FL3 的差异是否仍可区分（FL3 的蓝行更强）。

只记录相机内 JPEG 与回放观感即可，不需要 RAW。

## 7. 验证边界

- 本次是纯离线资产变更：没有写相机、没有重拍、没有测色。
- 「48 槽统一后画面更接近 FX2」是依据矩阵数值方向的推断，不是测量结果。
- Gamma 仍是 A7C2 的 4 条记录，照片主曲线只是采样点与 FX2 相同，整条不相等。
- 0.2.0 的 ZIP 保留作 A/B 对照，不要删除。
