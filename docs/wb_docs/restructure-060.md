# 0.6.0 重构：目录约定、备份校验、USB 兼容、独立还原

这一版只改工程结构与流程编排，**没有改动任何补丁数值**。
色彩资产、Gamma 窗口、cpapp-b.bin 与 appFw.so 的目标杂凑全部沿用 0.5.2，
`core.ORIGINAL` / `core.FINAL` 一字未动。

## 目录：不再让用户手选路径

| 位置 | 内容 | 规则 |
|---|---|---|
| `workdir/<时间戳>-<机身短码>/` | 每次工作一份 | 自动新建，永不复用旧目录 |
| `backup/<机身短码>/` | 每个机身一份已验证备份 | 重复备份只更新同一处 |

会话目录内部沿用 0.1.0 起的结构（`original/`、`candidate/`、`readback/`、
`evidence/`、`state.json`），旧版本留下的记录依旧能读懂。
启动脚本会在第一次运行时建好 `workdir/` 与 `backup/`。

## USB：同时兼容 WinUSB 与 libusbK

相机有两个 USB 身份，两个都要能打开：

* `054C:0E8A` —— 插上就出现的海量存储身份
* `054C:0336` —— 主机认证后由相机切过去的 SonyUSBDevice 服务身份

`usbdev.py` 用 PowerShell 读设备绑定的驱动服务名，只要落在
`{WinUSB, libusbK, libusb0}` 之一就算通过，再用 libusb 实际打开做二次确认；
读不到系统信息时退回「能不能打开」作为唯一判据。不强制某一种驱动。

`usbdev.preflight()` 就是「检查」按钮的完整流程：
验 0E8A 驱动 → 认证并切到 0336 → 复验 0336 驱动。

## 备份：三层校验，保证是原厂未打补丁的状态

1. **完整性**：清单里每个文件的 SHA-256 与记录一致（防篡改、防拷贝损坏）。
2. **原厂性**：两个完整程序与 `core.ORIGINAL` 逐字节一致。
3. **未打 FL2／FL3 补丁**：
   * AP 绑定槽 `0x02CF1287`／`0x02CF1289` 为空；
   * CP 色彩单元里 FL2／FL3 的参数映射为空（unit01 `0x1200+55/56`、
     unit0d `0x196+55/56` 均为 0）；
   * 目标色彩槽没有数据。

任一层不过，备份就不被还原与安装接受，界面上会显示红色「未找到通过校验的备份」。

## 流程

* **检查** —— 见上，两次驱动验证。
* **备份** —— 已有已验证备份时按钮禁用。
* **安装** —— 没有备份就先自动备份；已有备份则只读回一次确认机身仍是初始状态，
  读回后等 5 秒让 USB 身份刷新，再写入（`workflow.INSTALL_REFRESH_SECONDS`）。
* **还原** —— 独立入口 `workflow.restore_from_backup()`，只依赖备份库，
  不依赖某次工作目录；没有通过校验的备份就拒绝执行。
* **重启后核对** —— 沿用原有判据。

## 模块划分

| 文件 | 职责 | 是否接触 USB |
|---|---|---|
| `core.py` | 离线判据与补丁应用 | 否 |
| `layout.py` | `workdir/` 与 `backup/` 路径约定 | 否 |
| `usbdev.py` | 后端、驱动识别、模式切换 | 是（唯一入口之一） |
| `transport.py` | 有界服务会话与 Jiritsu 通道 | 是 |
| `backup.py` | 备份写入与三层校验 | 否 |
| `workflow.py` | 检查／备份／安装／还原编排 | 间接 |
| `app.py` | 命令行入口 | 间接 |
| `gui.py` | 简体中文界面 | 否（启动子进程） |
