# A7C II 桌面工具（开发预览）

适用于 ILCE-7CM2、固件 2.01。此版本把连接、Recovery、FL23、自定义外观、竖屏显示、电子快门声音放在同一个窗口。启动软件不会连接或改写相机。界面与整合流程仍需一起做实机测试。

## 一键还原

进入 **完整恢复 → 一键还原**，在弹窗中确认供电充足。程序在一个服务会话内识别已连接的机身，从已登记或所选备份目录中选择**这台机身最早可用的完整备份**，保存恢复前状态，再恢复程序、名称和项目涉及的创意外观设置，并完整读回。后续装过 FL23、LUT 或改过项目程序，不要求按安装顺序卸载，也不检查原厂固件哈希白名单。

它不会凭空生成原厂备份。“最早可用”只指本机已登记或指定目录能找到的备份，不保证是相机历史上第一次备份。如果旧备份在其他地方，直接选择**备份目录／备份 ZIP → 恢复所选备份**；旧 FL23 原始 backup2 也走这个入口，无需 LUT Job。

完成读回后，等程序提示所有 USB 读写结束，拔掉 USB 与其他供电，正常关机、等待存取灯熄灭，取出电池至少一分钟再开机。确认取景、拍照和回放正常后，接回并点 **核对恢复后加载状态**。完整读回不等于实机已经正常启动。

**恢复范围：**AP／CP 程序、已备份名称资源和项目创意外观字段；保留机身校准、计数器和无关设置。不是整个闪存的扇区镜像。原始旧 backup2 未保存独立的历史闪存配方快照，会采用当时保存的 RAM 配方记录。额外声音文件或竖屏别名不是旧备份的一部分；恢复旧程序后相关代码路径不再启用，文件清理应使用相应功能入口。

**使用条件：**相机还必须能进入服务通信；此入口不是无法连接机身的救砖程序。官方 `BODYDATA.DAT` 不是本工具的备份格式。

## “假降级”是否能还原？

[a7c2-service-preload](https://github.com/YuuLuo/a7c2-service-preload) 当前公开了服务认证、临时 root 执行和预加载机制说明，未提供可下载的“假降级恢复工具”，也未证明可以直接把官方 2.01 当作同版本更新重刷。临时代码执行不会永久关闭固件签名检查。因此当前的一键还原使用自己的备份，尚未加入官方固件假降级。

## 其他入口

| 入口 | 使用方式 |
| --- | --- |
| 连接与驱动 | Windows 检测并保留可用的 WinUSB／libusbK／libusb0 驱动；需要时仅安装相机 USB ID 对应的 WinUSB。macOS 使用 libusb，无需 Zadig。 |
| FL2／FL3 | 备份与准备 → 安装 → 完整断电重开 → 核对。 |
| 自定义创意外观 | 选择 `.a7look`、名称和栏位 → 备份与准备 → 写入 → 重开后检查预览和照片。可恢复单槽；旁边提供编译器和 LrC 插件安装按钮。 |
| 竖屏显示 | 开启拍摄信息／图标／布局随竖握转向；不是整个 MENU 旋转。目前开关作用于本次运行，重新加载后可能要再次开启。 |
| 电子快门声音 | 开启原生声音；自定义片段需先转换、机内试听、确认并恢复试听状态，再保存。 |

失败时保留任务目录，点 **导出诊断包**。程序保存完整异常和原始错误；不会自动重试未知结果的刷写。诊断包含本机路径与设备信息，发公开 issue 前请先检查。

界面不再要求输入电量。每次写入／还原前都会弹窗，提醒电量充足（建议至少 50%），并保持供电和 USB 连接；确认只对本次操作有效。当前没有经过验证的服务模式电量百分比接口，所以记录为“用户确认供电充足”，不会填入假定百分比。管理员驱动任务会实时回传阶段日志；Windows 命令有超时，原始输出另行保留。

**卸载 Windows 驱动：**在连接页点击“卸载相机驱动，恢复 Windows 默认连接”，确认并同意管理员授权。工具先导出备份，再卸载仅用于 `054C:0E8A／0336` 的第三方驱动包；保留 Windows 自带驱动。完成后拔插 USB，选择海量存储模式，让 Windows 重新识别。此操作不改写相机固件；重新使用刷写功能时再准备驱动即可。

开发者运行：安装 `desktop-requirements.txt` 后执行 `python desktop.py`。开发分支提供离线测试与 Windows／macOS 打包脚本；Mac USB 与桌面整合未经实机验证时，不应标成已验证。
